# Учебный сервер

Готовый к публикации в облачном Git репозиторий только с сервером.
Материалы курсов в Git не входят: папка `COURSE` подключена отдельным
volume и игнорируется правилами Git. Аккаунты, группы и привязка курсов
хранятся в SQLite внутри `data/`.

## Состав

```text
study-server/
├── server.py                 # HTTP-сервер на стандартной библиотеке Python
├── accounts.py               # SQLite: пользователи, группы, привязка курсов
├── index.html                # Главная страница
├── app.js                    # Клиентская логика
├── styles.css                # Стили
├── login.html                # Страница входа
├── login.js                  # Логика входа
├── admin.html                # Страница административного режима
├── admin.js                  # Логика админ-диалога и управления
├── admin.css                 # Стили админ-режима
├── system_prompt.txt         # Системный промпт целевой модели по умолчанию
├── tests/                    # Модульные тесты серверной валидации
├── data/                     # SQLite-база (не входит в Git и Docker-образ)
├── COURSE/.gitkeep           # Пустая папка для курсов
├── Dockerfile                # Образ приложения
├── docker-compose.yml        # Запуск на порту хоста
├── docker-compose.prod.yml   # Приложение + Caddy с HTTPS
├── Caddyfile                 # Конфигурация reverse proxy
├── .env.example              # Пример переменных окружения
├── .gitignore
├── .dockerignore
├── .gitattributes
└── README.md
```

Сервер не требует сторонних Python-пакетов. Используются только возможности
Python 3.12.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HOST` | `0.0.0.0` | Адрес прослушивания |
| `PORT` | `8000` | Порт приложения |
| `APP_PORT` | `8000` | Порт на хосте для `docker-compose.yml` |
| `DOMAIN` | нет | Домен для HTTPS в `docker-compose.prod.yml` |
| `CHIEF_USERNAME` | `admin` | Логин главного администратора |
| `ADMIN_PASSWORD_HASH` | нет | Хеш пароля главного администратора в формате `pbkdf2_sha256:<iterations>:<salt_hex>:<hash_hex>` |
| `ADMIN_PASSWORD` | нет | Простой пароль главного администратора только для локальной разработки |
| `ADMIN_SESSION_TTL` | `28800` | Время жизни сессии в секундах |
| `STUDY_DB_PATH` | `data/study.db` | Путь к SQLite-базе аккаунтов |
| `ADMIN_COOKIE_SECURE` | `0` (`1` в prod-compose) | `1` — выдавать cookie только по HTTPS |
| `TRUST_PROXY` | `0` (`1` в prod-compose) | `1` — доверять `X-Forwarded-For` (за Caddy) |
| `GUARD_BASE_URL` | `https://routerai.ru/api/v1` | Base URL контрольной модели |
| `GUARD_MODEL` | нет | Идентификатор контрольной модели |
| `GUARD_API_KEY` | нет | API-ключ контрольной модели |
| `GUARD_TIMEOUT` | `30` | Таймаут контрольного вызова в секундах |
| `TARGET_TIMEOUT` | `180` | Таймаут целевой модели в секундах |

При локальном запуске `server.py` автоматически читает `.env` из папки
`study-server`. Переменные, уже заданные в окружении, имеют приоритет.

Для production-запуска скопируйте пример и укажите свой домен:

```bash
cp .env.example .env
```

## Локальный запуск без Docker

Сервер автоматически читает `.env` из папки `study-server`. Уже заданные
переменные окружения имеют приоритет и не переопределяются. Запускайте именно
этот файл, а не другой `server.py` из соседней папки:

```bash
cd study-server
python server.py
```

Проверка:

```text
http://localhost:8000/login
http://localhost:8000/healthz
http://localhost:8000/admin
```

Главная страница, курсы и файлы материалов требуют входа. Главный
администратор входит под логином из `CHIEF_USERNAME` и паролем из
`ADMIN_PASSWORD_HASH`/`ADMIN_PASSWORD`.

## Локальный запуск в Docker

```bash
docker compose up -d --build
docker compose ps
```

Приложение будет доступно на `http://localhost:8000`.
Остановка:

```bash
docker compose down
```

## Публикация на VPS с HTTPS

Требуется сервер с Linux, домен и открытые порты `80` и `443`.

1. Направьте A-запись домена на IP сервера.
2. Установите Docker Engine и Compose plugin.
3. Клонируйте репозиторий и перейдите в папку:

```bash
git clone https://github.com/USER/REPO.git study-server
cd study-server
```

4. Создайте `.env` и укажите домен:

```bash
cp .env.example .env
nano .env
```

```dotenv
DOMAIN=study.example.com
```

5. Запустите приложение и Caddy:

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
```

6. Проверьте:

```bash
curl https://study.example.com/healthz
```

Caddy автоматически получит HTTPS-сертификат и будет проксировать запросы
на `app:8000`. Порты `80` и `443` должны быть доступны из интернета.

### Обновление на сервере

```bash
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

### Запуск без домена

Если HTTPS пока не нужен, можно открыть приложение напрямую:

```bash
cp .env.example .env
docker compose up -d --build
```

В этом случае приложение доступно на `http://IP-СЕРВЕРА:8000`. Для публичного
production-доступа используйте вариант с Caddy и доменом.

## Роли и доступ

- **Главный администратор** — видит все группы, курсы и пользователей;
  создаёт администраторов вместе с группами, создаёт и редактирует
  пользователей, распределяет курсы по группам.
- **Администратор** — владелец одной группы. Видит только свою группу,
  управляет её курсами и пользователями, может проходить курсы группы.
- **Пользователь** — относится к одной группе, видит только курсы этой группы
  и не имеет доступа к `/admin`.

Главная страница, `/admin` и файлы `COURSE/...` требуют входа. Чужие курсы
и файлы отдают `404`.

## Административный режим

Админ-режим доступен по адресу `/admin` для главного администратора и
администраторов групп. В нём можно вести диалог с выбранной моделью,
создавать и изменять курсы, управлять пользователями и привязкой курсов
к группам.

### Главный администратор

Логин задаётся в `CHIEF_USERNAME` (по умолчанию `admin`), пароль — в
`ADMIN_PASSWORD_HASH` или `ADMIN_PASSWORD`. При локальном запуске `server.py`
читает `.env` автоматически. Хеш создаётся командой:

```bash
python -c "import hashlib,os; s=os.urandom(16); h=hashlib.pbkdf2_hmac('sha256', b'ВАШ_ПАРОЛЬ', s, 260000); print('pbkdf2_sha256:260000:'+s.hex()+':'+h.hex())"
```

Для локальной разработки можно временно задать `ADMIN_PASSWORD`. Если заданы
оба параметра, используется хеш. Без пароля главный администратор не сможет
войти; обычные аккаунты из базы при этом продолжат работать.

### Аккаунты, группы и пользователи

Пользователи и группы хранятся в SQLite `data/study.db`. Пароли хранятся
в виде PBKDF2-хешей. При первом запуске база создаётся автоматически.

- главный администратор создаёт группу вместе с её администратором;
- у группы один администратор;
- администратор создаёт пользователей только своей группы;
- главный администратор может сбросить пароль, изменить логин, отключить
  или включить любого администратора/пользователя;
- администратор может делать это для пользователей своей группы;
- пользователь должен быть привязан к группе;
- существующие курсы остаются без группы и видны только главному
  администратору, пока он не привяжет их к группе;
- главный администратор привязывает курс через выбор группы в контексте
  и кнопку «Привязать курс к группе». Пустая группа отвязывает курс.

Сессия хранится в памяти сервера и действует `ADMIN_SESSION_TTL` секунд
(по умолчанию 8 часов). После перезапуска сервера требуется повторный вход.
Неудачные попытки входа ограничиваются по IP. При сбросе пароля или
отключении аккаунта его активные сессии завершаются.

### Контрольная модель

Перед каждым запросом к целевой модели сервер вызывает контрольную модель,
доступ к которой хранится только на сервере:

```dotenv
GUARD_BASE_URL=https://routerai.ru/api/v1
GUARD_MODEL=...
GUARD_API_KEY=...
```

Поддерживается OpenAI-совместимый API. Контрольная модель проверяет запрос на
безопасность и разрешает только создание и изменение курсов и учебных дней.
Целевая модель должна отличаться от контрольной.
Если контрольная модель не настроена, недоступна или вернула некорректный
ответ, запрос не передаётся целевой модели.

### Настройка целевой модели

Base URL, модель, API-ключ, temperature, top-p и максимальное число токенов
задаются в диалоговом окне `/admin`. Эти настройки хранятся только в
`localStorage` браузера, не сохраняются на сервере и передаются в теле каждого
запроса. Сервер использует их только на время запроса и не пишет в файлы,
`.env` или логи.

В админке используется OpenAI-совместимый API (`/chat/completions`).
По умолчанию лимит вывода — максимальный: `131072` токена.

Системный промпт задаётся на сервере: по умолчанию он хранится в
`system_prompt.txt`. В административном интерфейсе системный промпт не
отображается и не редактируется.

### Создание курсов и учебных дней

Целевая модель возвращает текстовый ответ и структурированный список
изменений. Администратор видит предпросмотр файлов и нажимает «Применить».
Сервер повторно проверяет операции, идентификаторы, пути и размеры файлов,
после чего записывает их в `COURSE`.

- `create_course` создаёт `main.md` и, при необходимости, дни;
- `update_course` заменяет `main.md`;
- `create_day` создаёт `dayN_theory.md` и `dayN_practice.md`;
- `update_day` изменяет файлы существующего дня.

Оба файла дня обязательны. Заголовок `### День N. Тема` в плане `main.md`
обновляется сервером автоматически. Перед изменением существующих файлов
создаётся резервная копия в `COURSE/.backups/`. Удаление курсов и дней не
поддерживается.

Выбранные в админке группа, курс и день передаются в контрольную и целевую
модель: они добавляются в системный промпт и в текст последнего
пользовательского сообщения. В диалоге это отображается бейджем «Контекст».
Сервер проверяет права на группу при каждом применении изменений: администратор
не может создать или изменить курс другой группы.

Сервер проверяет, что ответ модели полностью закрыт. Если модель обрывает
JSON, изменения не применяются. В этом случае уменьшите объём ответа (меньше
дней или короче материалы) либо увеличьте максимальное число токенов.

### Доступ к материалам

Просмотр курсов закрыт авторизацией. Сервер фильтрует список курсов по группе
пользователя и проверяет группу при каждом запросе файла из `COURSE/...`.
Курсы без привязки к группе доступны только главному администратору.

## Добавление курсов

Курсы не попадают в Git и в Docker-образ благодаря правилам `COURSE/*`.
На сервере они должны лежать в папке `COURSE` рядом с `docker-compose.yml`.
Она подключена в контейнер для чтения и записи, потому что админ-режим
создаёт и изменяет файлы курсов:

```text
./COURSE  -> /app/COURSE
study_data -> /app/data
```

`study_data` — named volume для SQLite-базы. Без него аккаунты и привязка
курсов к группам будут теряться при пересоздании контейнера.
Пользователь контейнера `app` должен иметь права на запись в `COURSE`.
Если при монтировании возникают ошибки доступа, узнайте UID пользователя
командой `docker compose exec app id` и назначьте владельца папки на хосте
либо используйте named volume.

Скопируйте курс на сервер, например:

```bash
scp -r ./COURSE/KAFKA user@server:/opt/study-server/COURSE/
```

После копирования откройте сайт и нажмите «Обновить список».
Сервер пересканирует `COURSE` при каждом запросе `/api/courses`, перезапуск
контейнера не требуется. Новый курс без привязки виден только главному
администратору — привяжите его к группе в `/admin`.

Если нужно намеренно хранить курсы в Git, удалите или измените строки
`COURSE/*` и `!COURSE/.gitkeep` в `.gitignore`. Аналогичные строки в
`.dockerignore` управляют попаданием курсов в Docker-образ.

## Заливка в облачный Git

Репозиторий уже можно инициализировать в этой папке:

```bash
cd study-server
git init -b main
git add .
git commit -m "Initial study server deployment"
git remote add origin https://github.com/USER/REPO.git
git push -u origin main
```

Для GitLab замените URL на адрес своего проекта. Файл `.env` не будет
закоммичен, потому что он исключён в `.gitignore`.

## Деплой в облачный PaaS

Dockerfile подходит для Render, Railway, Fly.io и аналогичных сервисов.

- Выберите деплой из Git-репозитория и тип Docker.
- Health check path: `/healthz`.
- Приложение само читает переменную `PORT`, которую передаёт платформа.
- Внутренний порт контейнера: `8000`.

В PaaS файловая система контейнера обычно временная. Чтобы курсы и аккаунты
сохранялись, подключите persistent volume к `/app/COURSE` и `/app/data`.
Если volume для курсов недоступен, можно включить курсы в образ: уберите
правила `COURSE/*` из `.dockerignore` и пересоберите контейнер. Базу `data/`
в образ включать не нужно.

## Ограничение доступа

Доступ к сайту, курсам и файлам материалов закрыт встроенной авторизацией
по логину и паролю. Дополнительный basic auth в Caddy не требуется.

## Безопасность

- `server.py` не отдаёт скрытые файлы, `.env`, Dockerfile, compose-файлы,
  каталог логов, каталог тестов и каталог `data` с SQLite-базой.
- Контейнер работает от непривилегированного пользователя `app`.
- Папка курсов монтируется для чтения и записи, потому что админ-режим
  создаёт файлы. Запись выполняет только процесс сервера после проверки роли,
  группы, контрольной модели и серверной валидации.
- Пароли обычных аккаунтов хранятся в SQLite в виде PBKDF2-хешей.
  Пароль главного администратора задаётся только через `.env`.
- Каждый запрос к `/api/courses` и к файлам `COURSE/...` проверяет сессию и
  группу. Пользователь не может получить чужой курс по прямому URL.
- Администраторы и пользователи не могут создавать или изменять курсы вне
  своей группы; это проверяется на сервере до записи файлов.
- Контрольная модель обязательна для админ-диалога. При её недоступности
  запрос отклоняется, а не передаётся целевой модели.
- Настройки целевой модели и её API-ключ хранятся в браузере администратора и
  не сохраняются на сервере. Не используйте админ-режим на общем компьютере.
- Для production используйте HTTPS через Caddy и `ADMIN_COOKIE_SECURE=1`.
- Не коммитьте `.env` и не публикуйте пароли, хеши и API-ключи.
